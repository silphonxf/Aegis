# 飞书 IP 研判与山石永久封禁

## 目标

Aegis 通过飞书机器人接收单聊或群聊中的 IPv4 查询，调用现有微步威胁情报能力生成卡片。拥有封禁权限的人员可以在卡片中选择恶意 IP、确认济南 IP，并将最终列表永久加入指定山石 StoneOS 地址簿。

本阶段只允许 `test-primary` 一台测试设备参与执行。第二台设备使用不同的 `target_code` 保存，明确设为非默认目标后再联调。

## 安全边界

- 飞书长连接只从 Aegis 主动访问飞书，不需要公网回调地址。
- 单聊直接响应；群聊只有明确 @ 机器人时响应。
- 第一次联系机器人的飞书用户只会登记 open_id，默认没有任何权限。
- 管理端按 open_id 绑定 Aegis 用户。永久封禁权限只能授予启用中的 `admin` 或 `super_admin`。
- 不按飞书显示名称自动授权。张晓帆也必须先发消息取得 open_id，再由超级管理员绑定。
- 卡片按钮只提交不可猜测批次 UUID 和固定动作名；IP、研判结果和设备目标均从数据库重新读取。
- 批次 30 分钟过期。消息和卡片事件在数据库中幂等去重。
- 单人可完成确认，不要求申请人/审批人分离；每次卡片操作仍会重新校验权限。
- 济南 IP 必须经过独立的二次确认按钮，之后还要执行最终确认。
- 真实执行是永久加入地址簿，不设置自动解封时间。
- 山石批量执行采用一次登录、一次读取、一次整体 PUT、一次回读核验；按设备和地址簿串行更新，降低覆盖风险。

## 飞书后台配置

1. 立即重置任何曾出现在聊天、截图或日志中的 App Secret。
2. 在应用中启用机器人能力。
3. 开通收取消息、以机器人身份发消息、更新卡片所需权限。
4. 使用长连接接收事件，订阅消息接收事件和卡片操作事件。
5. 发布应用版本，并确保张晓帆及测试群在应用可用范围内。
6. 只把重置后的 App Secret 写入服务器环境变量或密钥管理系统，不写入仓库。

环境变量：

```bash
FEISHU_APP_ID=cli_your_app_id
FEISHU_APP_SECRET=your_rotated_secret
FEISHU_FIREWALL_TARGET_CODE=test-primary
FEISHU_ALLOW_NON_TEST_FIREWALL_TARGETS=false
```

## Aegis 部署

在后端目录安装依赖并升级数据库：

```bash
cd /path/to/Aegis/code/backend
../../.venv/bin/pip install -r requirements.txt
../../.venv/bin/alembic upgrade head
```

按现有方式启动 Aegis HTTPS API，再用独立服务运行飞书桥：

```bash
cd /path/to/Aegis/code/backend
PYTHONPATH=. ../../.venv/bin/python -m app.integrations.feishu.runner
```

生产环境应使用 Windows 服务、systemd、Supervisor 或同类守护方式管理桥进程，并设置失败自动重启。桥进程与 API 共享数据库配置，但不需要监听端口。

## 首次授权张晓帆

1. 张晓帆在飞书单聊机器人发送任意消息。
2. 机器人回复尚未授权并展示 open_id。
3. 超级管理员登录 Aegis 管理端，进入“IP / 域名恶意研判”。
4. 在“飞书安全响应权限”刷新身份列表，选择张晓帆。
5. 绑定一个启用中的 Aegis `admin` 或 `super_admin` 用户 ID。
6. 同时开启“IP 查询权限”和“永久封禁权限”，保存。
7. 检查身份列表中只有张晓帆拥有封禁权限。

## 测试顺序

1. 配置 `test-primary`，验证账号、地址簿名和策略引用对象；保持“测试设备”为“是”。
2. 先在飞书查询一个已批准的测试 IP，选择“建议封禁”。
3. 点击“仅演练”，确认卡片显示演练完成，山石没有变化。
4. 使用一个不影响生产流量、已获得变更许可的 IP 做真实测试。
5. 点击“确认永久封禁”，在山石控制台核对地址簿，并核对 Aegis 审计日志。
6. 济南规则另做一次测试，确认未点击济南二次确认时无法执行。

由于当前地址簿已被策略引用，真实测试会立即产生策略效果。执行前必须自行选定安全的测试 IP 和维护窗口。本实现不会自动对真实设备发起测试。

## 第二台设备

第二台设备后续以新的 `target_code` 保存，例如 `prod-secondary`，并设置：

- `is_default=false`
- `is_test_target=false`
- 独立的主机地址、账号密文和地址簿名

在完成独立登录、读取、演练、真实写入和回读验证前，不要把 `FEISHU_FIREWALL_TARGET_CODE` 切换到第二台设备。
完成验证并正式批准启用生产目标后，还需要显式设置
`FEISHU_ALLOW_NON_TEST_FIREWALL_TARGETS=true`；默认值为 `false`，用于防止误切到第二台设备。

## 回滚

当前阶段只实现永久封禁，没有自动解封按钮。误封时需由山石管理员从地址簿中人工删除 IP 并验证策略结果，同时保留 Aegis 审计记录。上线生产前建议增加“解封批次 + 回读核验 + 单独权限”能力。
