# Aegis 管理端 V2.0 前端实施文档

> 基于《运维工具管理端（Admin Console）V2.0 重构设计文档》整理的前端落地版，目标是把产品结构进一步压缩成可直接开发的页面、组件、字段与交互规则。

---

## 1. 实施目标

本实施文档只解决前端落地问题，重点回答 4 件事：

1. 左侧菜单怎么重组
2. 每个模块页面怎么拆
3. 每个页面最少需要哪些组件
4. 哪些交互先做、哪些后做

目标不是一次做完全部复杂联动，而是先把管理端 V2.0 的 **页面骨架、信息架构和关键交互** 落下来。

---

## 2. 一级导航结构

管理端左侧导航调整为 4 个一级模块：

1. **监控大盘**
2. **资产与日常运维**
3. **应急预案配置**
4. **运维审批与审计**

### 2.1 导航映射建议

| 现有页面/能力 | V2.0 新归属 |
|---|---|
| Dashboard Overview | 监控大盘 |
| 用户管理 | 资产与日常运维 / 基础数据录入 |
| 系统管理 | 资产与日常运维 / 系统自检配置与记录 |
| 模板管理 | 资产与日常运维 / 系统自检配置与记录 |
| 巡检相关 | 资产与日常运维 / 机房巡检配置与记录 |
| 资产管理 | 资产与日常运维 / 基础数据录入 |
| SSH / 服务器 / 数据库 / 进程动作 | 应急预案配置 |
| 工具任务审批 | 运维审批与审计 |
| 审计日志 | 运维审批与审计 |
| AI诊断 / 规则与审计 / 调试 | 暂挂到运维审批与审计或后续二期整理 |

## 3. 页面拆分方案

## 3.1 监控大盘

### 页面目标
首屏展示全局状态，并提供向其他模块的跳转入口。

### 建议组件

1. **KPI 卡片区**
   - 绿色系统数
   - 黄色系统数
   - 红色系统数
   - 总系统数

2. **资源指标区**
   - CPU
   - 内存
   - 磁盘
   - sparkline 趋势

3. **异常系统表格**
   - 系统名称
   - 环境
   - 状态
   - CPU/MEM/DISK
   - 最近采集时间
   - 操作：查看详情

4. **待办摘要区**
   - 待审批数量
   - 今日异常自检数量
   - 今日异常巡检数量
   - 最近高风险操作数量

### 首版建议
- 保留现有 dashboard 数据接口
- 先补“待办摘要区”占位
- 异常系统点击后跳到“资产与日常运维 / 系统自检 Tab”

---

## 3.2 资产与日常运维

这个模块首版建议做成一个页面内的 **三 Tab 工作台**。

### Tab 列表
1. **系统自检配置与记录**
2. **机房巡检配置与记录**
3. **基础数据录入**

---

### 3.2.1 Tab 1：系统自检配置与记录

#### 页面布局
推荐两栏布局：

- 左栏：系统配置表
- 右栏：系统自检记录表

#### 左栏组件

1. 搜索栏
   - 输入系统名
   - 搜索按钮
   - 新建系统按钮

2. 系统配置表格
   - 系统名称
   - 运行服务器 IP
   - 自检负责人
   - 检查频次
   - 最新状态
   - 最近填报时间
   - 操作

3. 新建/编辑系统弹窗
   - 系统名称
   - 运行服务器（多选下拉）
   - 自检负责人（多选下拉）
   - 检查频次
   - 关联预案（可选）
   - 备注

#### 右栏组件

1. 记录筛选栏
   - 状态筛选：全部 / 正常 / 异常 / 未填报
   - 导出按钮

2. 自检记录表格
   - 填报时间
   - 系统名称
   - 填报人
   - 状态
   - 异常说明
   - 是否已联动预案
   - 操作：详情

#### 首版交互建议
- “详情”先做 drawer / modal，不做新页面
- “一键处置”先跳 Runbook，并自动带系统名筛选
- “提醒”首版可以只弹确认，不先接真实通知

---

### 3.2.2 Tab 2：机房巡检配置与记录

#### 页面布局
推荐两栏布局：

- 左栏：机房/二维码管理
- 右栏：巡检历史

#### 左栏组件

1. 操作栏
   - 新增巡检机房

2. 机房表格
   - 机房/区域名称
   - 物理位置
   - 二维码 ID
   - 最近巡检人
   - 巡检结果
   - 巡检时间
   - 操作：生成二维码 / 下载二维码 / 编辑

3. 新建/编辑机房弹窗
   - 机房名称
   - 物理位置描述
   - 关联二维码编号（自动生成或只读）
   - 备注

#### 右栏组件

1. 搜索栏
   - 输入巡检人
   - 搜索

2. 巡检历史表格
   - 巡检时间
   - 机房名称
   - 巡检人
   - 结果
   - 备注
   - 操作：详情

#### 首版交互建议
- 二维码先支持生成文本/图片下载
- 详情先做 modal
- 异常行用红色 badge，高亮备注列

---

### 3.2.3 Tab 3：基础数据录入

建议再拆为两个分区：

1. 用户管理
2. 服务器/IP 基础数据

#### A. 用户管理组件

1. 顶部工具栏
   - 新增用户
   - 下载 Excel 模板
   - 批量导入

2. 用户表格
   - 姓名
   - 工号/账号
   - 联系电话
   - 系统角色
   - 负责系统数量
   - 操作：编辑 / 重置密码

3. 新建/编辑用户弹窗
   - 姓名
   - 工号/账号
   - 手机号
   - 系统角色
   - 默认密码（仅新增时）

#### B. 服务器/IP 基础数据组件

1. 工具栏
   - 新增服务器
   - 下载 Excel 模板
   - 批量导入

2. 服务器表格
   - 服务器名称
   - IP 地址
   - 端口
   - 所属系统
   - 所在机房
   - 连接方式
   - 操作：编辑

3. 新建/编辑服务器弹窗
   - 服务器名称
   - IP 地址
   - 端口
   - 所属系统
   - 所在机房
   - 连接方式
   - 备注

#### 首版交互建议
- 用户和服务器先用统一 modal 表单
- Excel 导入首版可只做文件上传和结果提示
- “负责系统数量”先后端返回汇总值，不在前端计算

## 3.3 应急预案配置（Runbook）

### 页面目标
把原来分散的 SSH / 服务器 / 数据库 / 进程动作页，统一成一个“预案脚本库”。

### 页面布局
推荐左右布局：

- 左栏：预案列表
- 右栏：执行历史 / 审批流

### 左栏组件

1. 搜索栏
   - 输入预案名称/系统
   - 搜索
   - 新建预案脚本

2. 预案表格
   - 预案名称
   - 适用系统
   - 目标执行服务器
   - SSH凭证关联
   - 触发机制
   - 最近执行时间
   - 风险等级
   - 操作：编辑代码 / 测试连接 / 启用停用

3. 新建/编辑预案弹窗
   - 预案名称
   - 适用系统（下拉）
   - 执行脚本（多行文本）
   - 目标执行服务器（高级项）
   - 触发机制（高级项）
   - 风险等级（高级项）
   - 备注

### 右栏组件

1. 状态筛选
   - 全部 / 待审批 / 执行成功 / 执行失败

2. 执行历史表格
   - 执行时间
   - 预案名称
   - 触发源/操作人
   - 目标 IP
   - 最终结果
   - 执行耗时
   - 终端日志入口

#### 首版交互建议
- “编辑代码”先用弹窗/抽屉，不单独做代码页
- “测试连接”先调用 mock 或已有 tool task 能力
- “终端实时日志”首版先展示执行输出快照

## 3.4 运维审批与审计

建议首版做成上下结构：

- 上半：审批流
- 下半：审计日志

### 3.4.1 审批流组件

1. 筛选栏
   - 状态筛选
   - 类型筛选
   - 系统筛选

2. 审批表格
   - 申请时间
   - 申请人
   - 审批类型
   - 关联对象/系统
   - 原因
   - 审批状态
   - 操作：同意 / 驳回 / 查看详情

3. 审批详情弹窗
   - 基本信息
   - 审批意见
   - 关联对象链接
   - 历史记录

### 3.4.2 审计日志组件

1. 筛选栏
   - 时间范围
   - 风险等级
   - 业务模块
   - 操作账号

2. 审计日志表格
   - 操作时间
   - 操作账号
   - 客户端 IP
   - 业务模块
   - 操作类型
   - 详细描述
   - 风险等级
   - 证据链/快照

#### 首版交互建议
- 高风险/极高危行整行浅红色高亮
- 操作账号、系统、预案名称支持点击跳转
- 快照先支持文本/JSON/执行输出查看

## 4. 公共组件清单

为了加快前端实施，建议优先沉淀以下公共组件：

1. **PageHeader**
   - 标题
   - 描述
   - 右侧操作区

2. **Toolbar**
   - 搜索框
   - 筛选器
   - 主按钮
   - 次按钮

3. **DataTable**
   - 统一表格头
   - 空状态
   - 加载状态
   - 操作列

4. **StatusBadge**
   - 正常 / 异常 / 待审批 / 已通过 / 已驳回 / 未填报

5. **RiskBadge**
   - 低 / 中 / 高 / 极高危

6. **FormModal**
   - 新建/编辑统一弹窗

7. **DetailDrawer**
   - 适合详情展示，不打断主列表

8. **EvidenceViewer**
   - 查看日志快照 / JSON / 执行输出

## 5. 前端状态管理建议

如果当前仍是原生 JS 结构，首版不必引入复杂状态管理框架，但建议把状态按模块整理：

- `dashboardState`
- `opsWorkbenchState`
- `runbookState`
- `approvalAuditState`

同时抽出统一：

- `api.request`
- `ui.modal`
- `ui.drawer`
- `ui.toast`
- `table.emptyState`

这样后续即使迁移到 Vue/React，也不会推倒重来。

## 7. 开发顺序建议

### 第一步：重组导航和页面骨架
先不深改接口，只完成：

- 左侧菜单重组
- 四大模块页面骨架
- 三 Tab 工作台骨架

### 第二步：把现有接口挂到新页面
优先复用现有能力：

- dashboard 数据
- 用户列表
- 系统列表
- 资产列表
- 巡检/自检记录
- 工具任务审批
- 审计日志

### 第三步：补弹窗与联动交互
完成：

- 新建系统
- 新建机房
- 新建用户
- 新建预案
- 基于系统名/ID 的联动跳转

### 第四步：做高危与审计增强
完成：

- 风险 badge
- 审批弹窗
- 快照查看
- 异常高亮

## 8. 与当前前端代码的衔接建议

当前 `frontend-admin` 已有这些现成区域：

- Dashboard
- 用户管理
- 系统管理
- 资产管理
- 工具审批
- 审计日志

所以首版不建议推倒重来，而建议：

1. 先改左侧菜单与 view 分组
2. 保留已有表格和接口请求函数
3. 用新页面容器重新组织旧模块
4. 把旧的“应急配置”拆页逐步收敛成 Runbook

这样风险最小，出效果最快。

---

## 9. 一句话实施策略

**先重组骨架，再迁移功能；先统一工作台，再补强联动；先做能看能点，再做高级自动化。**
