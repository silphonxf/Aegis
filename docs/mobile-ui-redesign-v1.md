# Aegis 移动端 UI 重构方案 v1

> 更新时间：2026-05-11
> 目标：将当前“顶部 tab + 工作台 + 子卡片 show/hide”的移动端原型，重构为更接近微信式移动应用的导航与页面模型，提升简洁度、一致性与可维护性。

---

## 1. 重构目标

当前移动端存在的问题：

1. 顶部主导航 + 工作台 + 子卡片层层嵌套，操作路径偏绕
2. 主任务（巡检 / 自检）与辅助工具（Ping / 抓包 / AI）混杂
3. 页面普遍以卡片块拼接，缺少“一个页面只做一件事”的完整性
4. 前端大量依赖 show/hide 子区块，结构复杂，易造成交互与脚本维护问题

本轮重构目标：

- 底部固定 4 个一级导航 Tab
- 一级页承担“摘要 + 导航”职责
- 二级功能统一改为全屏页面 push 进入
- “我的”仅保留账号相关内容
- Ping / 抓包 / AI 问答等辅助工具统一放入“工作台”的辅助工具区
- 建立统一页面模板，减少页面结构发散

---

## 2. 一级导航（底部 Tab）

移动端一级导航固定为：

1. **工作台**
2. **巡检**
3. **自检**
4. **我的**

### 2.1 一级导航职责

- **工作台**：首页，总览信息、待办、快捷操作、辅助工具入口
- **巡检**：巡检主工作区
- **自检**：自检与状态分析主工作区
- **我的**：账号与个人信息相关

### 2.2 设计规则

- 一级 Tab 之间是平级切换
- 切换 Tab 时展示该 Tab 的根页面
- 一级页不再通过 show/hide 卡片拼装二级页面
- 底部 Tab 长驻，保持移动端应用的一致性

---

## 3. 信息架构

## 3.1 工作台

### 定位
首页。用户进入 App 后应快速看到：
- 今天要做什么
- 当前是否有异常
- 最常用入口在哪里

### 页面结构

#### 模块 A：今日待办
- 今日待巡检
- 今日待自检
- 异常提醒

#### 模块 B：快捷操作
- 扫码巡检
- NFC 巡检
- 提交自检
- 系统状态

#### 模块 C：辅助工具
- AI 问答
- Ping
- 抓包分析
- 最近工具任务

#### 模块 D：最近动态
- 最近巡检记录
- 最近自检记录
- 最近异常摘要

---

## 3.2 巡检

### 定位
聚焦巡检工作，不混入其他排障工具。

### 页面结构
- 扫码巡检入口
- NFC 巡检入口
- 最近巡检记录

### 二级页面
- 扫码巡检页
- NFC 巡检页
- 巡检记录页
- 巡检记录详情页

---

## 3.3 自检

### 定位
聚焦系统自检闭环：看状态、提自检、看错误分析。

### 页面结构
- 系统状态
- 提交自检
- 错误日志分析

### 二级页面
- 系统状态页
- 自检提交页
- 错误日志分析页
- 日志详情页（可选）

---

## 3.4 我的

### 定位
只保留与账号和个人信息有关的功能。

### 页面结构
- 头像 / 昵称 / 用户名 / 角色
- 修改密码
- 当前版本 / 关于应用（可选）
- 退出登录

### 明确保留规则
“我的”中 **不放**：
- AI 问答
- Ping
- 抓包分析
- 工具任务

---

## 4. 页面切换模型

## 4.1 一级切换

底部 Tab 在以下页面之间切换：
- 工作台
- 巡检
- 自检
- 我的

规则：
- 平级切换
- 进入后始终回到该一级页根视图
- 不保留旧的 show/hide 子页面状态

## 4.2 二级页面打开方式

所有功能入口统一采用：
- 点击后进入 **全屏页面**
- 顶部显示返回箭头与标题
- 返回时回到来源一级页

示例：
- 工作台 -> AI 问答
- 工作台 -> Ping
- 工作台 -> 抓包分析
- 巡检 -> 扫码巡检
- 自检 -> 系统状态

## 4.3 三级页面/弹层

更细粒度的内容根据语义分流：

### 全屏三级页
适合：
- 巡检记录详情
- 工具任务详情
- 日志详情
- AI 会话详情

### 弹层 / Action Sheet / Drawer
适合：
- 轻量选择器
- 上传附件预览
- 危险操作确认
- 页面内局部工具菜单

---

## 5. 重点页面定义

## 5.1 扫码巡检页

### 页面结构
- 顶部：返回 + 标题
- 中部：扫码状态 / 巡检点识别结果
- 表单区：结果、备注
- 底部主按钮：提交巡检

### 交互原则
- 点“开始扫码”后调用相机
- 识别成功后自动回填点位信息
- 提交成功后提供“返回 / 继续下一次”反馈

---

## 5.2 NFC 巡检页

页面结构与扫码巡检页尽量同构：
- 读取标签
- 显示点位
- 填结果
- 提交

目的：
- 减少学习成本
- 保持巡检体验一致

---

## 5.3 系统状态页

### 页面结构
- 系统选择器
- 状态摘要卡
- CPU / MEM / DISK 图表
- 最近巡检 / 自检结果摘要

### 设计原则
- 避免多个图表生硬堆叠
- 优先用“概况卡 + 轻图表”结构
- 强化系统状态一眼可读性

---

## 5.4 自检提交页

### 页面结构
- 自检内容
- 自检结果
- 备注
- 底部提交按钮

### 设计原则
- 极简表单页
- 一个页面只服务“提交一次自检”

---

## 5.5 错误日志分析页

### 页面结构
- 时间范围
- 严重级别
- 提取日志
- AI 分析
- 日志展示区
- AI 结果展示区

### 设计原则
- 更像分析台，而不是普通表单页
- 上半区操作、下半区结果
- 日志与 AI 输出层次分离

---

## 5.6 AI 问答页

### 页面结构
- 顶部：返回 + 标题
- 中部：聊天消息流
- 底部：输入框 + 上传附件 + 发送
- 可选：最近会话入口

### 设计原则
- 明显采用聊天页模型
- 不再使用卡片式拼装
- 输入区固定底部
- 附件作为轻量上下文附着于消息流

---

## 5.7 Ping 页

### 页面结构
- 主机
- 次数
- 执行按钮
- 结果区

### 设计原则
- 轻量、快速、单任务页面

---

## 5.8 抓包分析页

### 页面结构
- 来源
- 严重级别
- 备注
- 抓包内容输入区
- 导入最近请求
- AI 分析按钮
- 结果区

### 设计原则
- 采用“运维工具 / 分析器”风格
- 强化内容输入与结果输出

---

## 6. 视觉与交互风格

## 6.1 风格关键词
- 简洁
- 稳重
- 高信息效率
- 专业但不过度压抑
- 少炫技、少视觉噪音

## 6.2 一级页风格
- 少用大面积渐变重卡片
- 更偏列表、轻卡片、快捷入口块
- 模块边界清晰

## 6.3 二级页风格
- 标准全屏页
- 顶部返回
- 表单 / 工具内容垂直排布
- 底部主按钮固定或靠近底部

## 6.4 工具页风格
- AI / 抓包 / 日志分析偏深色工具感
- 但整体风格仍要与全局保持一致

## 8. 落地顺序建议

## 第 1 阶段：重构导航骨架
- 顶部 tab 改为底部 tab
- 重建一级页结构
- show/hide 子卡片模式切换为全屏页面容器

## 第 2 阶段：重排功能归属
- 拆掉“工具箱”作为主导航
- 将 AI / Ping / 抓包归入工作台辅助工具区
- “我的”只保留账号功能

## 第 3 阶段：重做重点页面
优先顺序：
1. 工作台
2. 巡检页
3. 自检页
4. AI 问答页
5. 系统状态页

## 第 4 阶段：统一视觉与交互细节
- 间距体系
- icon 体系
- loading / empty / error 状态
- 页面切换动效

---

## 9. 本轮确认下来的产品规则

1. 底部 4 tab 固定为：**工作台 / 巡检 / 自检 / 我的**
2. **我的只放账号相关内容**
3. **Ping / 抓包 / AI 问答归入工作台辅助工具区**
4. **所有二级功能统一全屏打开**
5. **一级页负责导航与摘要，二级页负责完成任务**
6. **不再继续扩展“工具箱”作为一级导航**

---

## 10. 下一步建议

下一步直接进入前端骨架重构：

1. 改造 `frontend-mobile/index.html` 页面结构
2. 改造 `frontend-mobile/style.css` 以适配底部 Tab + 全屏页面布局
3. 改造 `frontend-mobile/app.js`，把当前基于 show/hide 子卡片的切换逻辑重构为：
   - 一级 tab 切换
   - 二级页面 push/pop
   - 页面栈或统一路由状态

本文件作为本轮 UI 重构的产品与结构依据。
