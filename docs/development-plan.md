# 运维助手（Aegis）开发计划 v0.1

## 1. 项目范围与模块拆分

### 1.1 业务模块
1. 巡检协助（扫码 / NFC）
2. 系统自查（日检 / 周检 / 年检）
3. 报表中心（巡检 + 自查）
4. 移动端工具箱（ping、抓包、重启等）
5. 资产管理（录入、批量导入、标签检索）
6. 后台管理（用户、角色、系统、模板）
7. 全局监控总览（超级管理员）
8. AI 扩展接口（离线模型排障）

### 1.2 建议的“系统状态”条目（易实现且实用）
- 主机在线状态（ICMP）
- 关键端口可达性（TCP 探活）
- CPU / 内存 / 磁盘使用率（阈值分级）
- 关键进程存活（如数据库、应用服务）
- 关键日志异常计数（近 24h ERROR）
- 最近备份时间与结果
- 最近一次巡检/自检结论

状态评级建议：
- 绿色：正常
- 黄色：关注（接近阈值）
- 红色：异常（超过阈值）

## 2. 技术架构建议（Python 全栈）

### 2.1 后端
- 框架：FastAPI
- ORM：SQLAlchemy 2.x
- 迁移：Alembic
- 认证：JWT + RBAC
- 任务调度：APScheduler / Celery（二期）
- 报表导出：Pandas + openpyxl

### 2.2 数据库
- 主库：达梦数据库（DM）
- 适配策略：
  - SQLAlchemy 方言 + 原生 SQL 双通道
  - 关键 SQL 统一封装（避免方言散落）
  - 提前定义兼容基线（国产 OS / CPU）

### 2.3 前端
- 移动端：优先 H5/PWA（便于快速落地）
- 管理端：Vue3 + Vite + Element Plus（或 Ant Design Vue）

### 2.4 部署
- Docker / Docker Compose
- 预留 K8s 清单（后续）
- 配置分层：dev/test/prod

## 3. 里程碑（建议 4 个迭代）

### 迭代 0（1 周）——需求固化与基础搭建
- 明确角色与权限模型
- 产出 ER 图 + 接口草案
- 建立仓库骨架、CI、代码规范

### 迭代 1（2 周）——MVP 核心闭环
- 登录认证、用户与角色
- 巡检记录（扫码录入）
- 自检模板 + 自检上报
- 基础报表查询（列表 + 时间筛选）

### 迭代 2（2~3 周）——管理与可视化
- 后台管理：用户/系统/模板管理
- 超级管理员全局看板（状态聚合）
- 资产管理（单录 + 批量导入）

### 迭代 3（2 周）——增强能力
- NFC 支持
- 移动端工具箱（ping/端口检查/重启任务）
- AI 诊断接口（先定义协议 + mock）

## 4. 首版数据模型（摘要）
- users / roles / permissions
- systems（被管系统）
- inspection_points（巡检点）
- inspection_records（巡检记录）
- checklist_templates（自检模板）
- selfcheck_records（自检记录）
- assets（资产台账）
- reports（报表快照，可选）
- tool_tasks（工具执行任务）

## 5. 风险与控制
- 达梦适配风险：第一周建立 POC + SQL 兼容清单
- 移动端硬件能力差异（NFC/扫码）：先抽象能力层
- 重启/抓包等高危操作：审批流 + 审计日志 + 最小权限
- AI 误判：仅做辅助建议，不直接执行变更
