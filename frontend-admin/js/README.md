# frontend-admin/js 模块说明

这是管理后台前端的轻量模块化目录。

## 目标
- 保留当前静态前端形态，不引入新框架
- 先把高复用、易膨胀的逻辑从 `app.js` 中拆出来
- 让 `app.js` 回归到“入口/装配层”职责

## 当前模块
- `api.js`
  - API base 计算
  - 通用请求封装
  - 请求历史记录
- `auth.js`
  - 登录
  - 退出登录
  - 登录态视图切换
  - token 失效后的强制回登录
- `dashboard.js`
  - dashboard 自动刷新
  - KPI / 技术指标 / 趋势图
- `toolbox.js`
  - 工具任务列表
  - 工具任务状态更新
  - 工具任务表格渲染
- `assets.js`
  - 资产筛选参数构建
  - 资产列表
  - 资产创建
- `users.js`
  - 用户查询
  - 用户列表渲染
- `systems.js`
  - 系统查询
  - 系统列表渲染
- `rules-audit.js`
  - 状态规则读取/保存
  - 审计日志筛选查询
- `templates.js`
  - 自检模板创建/查询
  - 状态快照提交
- `modals.js`
  - 创建用户/系统弹窗控制
  - 创建用户/系统提交逻辑
- `debug.js`
  - 调试区辅助动作
  - 清空请求历史 / 清空筛选条件

## 当前入口文件职责
`app.js` 现在仅负责：
- 初始化共享 `state`
- 绑定页面事件
- 调度各模块方法
- 处理少量组合层逻辑

## 后续建议
- 再往后可继续抽：
  - modal 相关逻辑
  - dashboard 的系统筛选/异常表格逻辑
  - 用户/系统创建逻辑
- 保持原则：先拆“公共逻辑”，再拆“高频业务块”，避免一次性大重构。
