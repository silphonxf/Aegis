Aegis 运维助手 Milestone Overview 聚焦 AI 持续迭代

Aegis 项目里程碑总览

Aegis 是一个面向移动端与后台管理的一体化运维助手，覆盖巡检、自检、监控、资产、工具箱、审批流、AI 诊断与 AI 问答等场景。 当前项目已经从“能演示”推进到“本地可联调、可持续迭代”的阶段，并且 AI 主链路已经完成从 skeleton 到真实 OpenClaw 接入。

当前总体状态：v1.0.0 主体功能完成 当前开发重心：AI 能力体验与稳定性增强 本地联调：已打通 局域网 / Tailscale 访问：已支持

里程碑演进

M1 · 产品主体功能落地

已完成
  • 完成认证、巡检、自检、报表、管理看板、资产管理、审计、工具箱基础能力。
  • 形成 v1.0.0 主体功能范围，具备整体演示能力。

M2 · 本地开发基线整理

已完成
  • 恢复默认 seed，支持本地启动后直接使用默认管理员登录。
  • 补齐本地脚本：dev-up / dev-stop / dev-reset / dev-status / dev-check。
  • 完善联调文档，降低新环境接手成本。

M3 · 回归测试与 Smoke 护栏

已完成
  • 补齐 auth、inspections、selfchecks、toolbox、ai、assets、systems、audit 等测试。
  • 增强 smoke 脚本，覆盖健康检查、登录、自检、工具任务、AI 诊断、资产 summary、审计日志等主链路。

M4 · 工具箱 / 审批流闭环增强

进行中 / 已完成第一阶段
  • 扩展工具任务状态机：pending_approval / approved / running / done / failed / rejected / cancelled。
  • 统一任务 result 结构，增强执行元数据、结构化日志与后台展示。
  • 移动端已能创建应用重启任务并查看最近工具任务。

M5 · AI 能力接入与升级

当前重点
  • 离线 AI（Ollama）已接入诊断与离线日志分析，保留规则引擎回退。
  • OpenClaw provider 抽象已完成，Aegis AI 问答 / AI 诊断已真实接入 OpenClaw。
  • 移动端 AI 问答已支持纯文本、图片/文件附件、对话气泡展示、聊天记录持久化。
  • 已修复：Tailscale 跨域、附件日志导致页面崩溃、图片 data_url 校验长度不足、聊天输入清空与气泡样式问题。

M6 · 下一阶段方向

下一步
  • 继续优化 AI 问答体验：附件策略、图片分析质量、会话上下文、提示词稳定性。
  • 提升移动端 AI 的“像真实聊天产品”的体验：loading 态、消息状态、附件卡片、异常恢复。
  • 进一步沉淀 AI 能力到产品化功能，而不是只停留在接口联调层。

已开发功能点梳理

1. 认证与账号体系

项目基础登录与用户身份能力已经具备。

  • 管理员登录 / Token 持久化
  • 当前用户信息读取（/auth/me）
  • 个人资料修改
  • 修改密码
  • 默认 seed 管理员自动初始化

2. 巡检模块（移动端）

覆盖机房巡检的移动端操作入口。

  • 二维码巡检
  • NFC 巡检入口
  • 巡检点解析
  • 巡检记录提交与查询

3. 自检模块

支持标准化自检与系统状态查看。

  • 自检模板创建与读取
  • 简化自检提交
  • 自检记录查询
  • 系统状态页（CPU / MEM / DISK 曲线）
  • 错误日志读取与 AI 分析入口

4. 工具箱与审批流

从简单工具接口扩展到任务化闭环。

  • Ping / 端口检测
  • 错误日志提取
  • 应用重启任务创建
  • 工具任务状态流转与审批
  • 结构化执行结果记录

5. 管理后台

管理端已具备可联调的核心运营能力。

  • 全局看板 / 监控总览
  • 用户管理
  • 系统管理
  • 模板管理
  • 状态规则读取 / 更新
  • 资产创建、批量导入、导出、summary
  • 审计日志查询
  • ThreatBook 相关接入

6. 数据与数据库适配

兼顾本地轻量联调与达梦环境接入。

  • SQLite 本地默认开发模式
  • 达梦 DATABASE_URL / 拆分 DM_* 配置支持
  • Alembic 迁移
  • 达梦检查脚本与验收增强

7. AI 诊断与离线分析

AI 能力已经进入实际主链路。

  • AI 诊断接口
  • 离线错误日志分析
  • 规则引擎回退
  • Ollama provider 接入
  • elapsed_ms / fallback_reason 观测增强

8. OpenClaw AI 问答（最新进展）

这是当前最值得继续深挖的方向。

  • Aegis AI provider 抽象已建立
  • OpenClaw gateway 本地真实接入已打通
  • 移动端 AI 问答支持文本 + 附件
  • 支持局域网 / Tailscale 访问
  • 支持聊天记录保留与 UI 基础优化

当前 AI 迭代现状

你现在已经不再是在做“把 AI 接上去”这一步了，而是在进入“把 AI 做好用”这个阶段。
  • OpenClaw 已经不是 skeleton/mock，而是真实接入。
  • 移动端 AI 问答已经具备产品雏形：消息区、输入区、附件、会话保留、局域网可访问。
  • 当前短板主要集中在体验稳定性与产品感，而不是基础连通性。

后续建议：AI 模块下一轮优化方向

体验层

  • 发送中 loading 气泡
  • 消息失败重试
  • 附件卡片化展示
  • 图片上传压缩 / 大小限制
  • 更好的移动端输入体验

能力层

  • 图片内容分析质量提升
  • 日志 / 文本附件提取策略优化
  • 会话上下文连续性增强
  • 更稳定的运维诊断提示词
  • 按场景切换 AI 工作模式（问答 / 诊断 / 日志分析）

工程层

  • AI 问答自动化测试补充
  • 附件大小、类型、异常处理护栏
  • 前端请求日志继续轻量化
  • OpenClaw provider 响应结构进一步标准化

产品层

  • 把 AI 从“工具箱里的子页面”升级成更核心能力
  • 考虑沉淀为：故障助手 / 日志助手 / 巡检助手
  • 让 AI 真正参与运维闭环，而不是仅做文本回复

建议你下一轮就围绕「AI 问答体验稳定化 + 附件策略 + 场景化诊断」继续推进，这样最能把 Aegis 的差异化做出来。
